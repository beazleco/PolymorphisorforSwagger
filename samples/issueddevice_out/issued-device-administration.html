How this was decided

For every row of every operation sheet the tool asked, in order:

  1. Does the workbook name an SOR field for this element? An empty SOR cell is the analyst saying the System of Record does not supply it, and the element is removed.
  2. Does that field exist in the System of Record? The endpoint comes from the sheet's SOR API Endpoint banner cell, which is the definitive statement of it. A Request Body row is looked up in that endpoint's request, meaning its body for POST and PUT or its parameters for GET, and a Response Body row in its response. Matching is on the last segment of the field name, so accountInfo.currency resolves to any element named currency. A field that is not there means the element is removed, and the removal is listed against its cell.
  3. Do all variants of the operation supply it? Where an operation is served by several SOR endpoints, an element supplied by some and not others appears only in those, through allOf inheritance from a shared base.
  4. Do other endpoints share this class? A class used by more than one endpoint with different content is split, so no endpoint is shown another endpoint's elements.

Only the SOR API Endpoint banner cell decides which SOR endpoint applies. An endpoint written on an SOR column header is a label: where the two differ the banner is used and the difference is reported, so the workbook can be tidied without the interface changing underneath anyone.
